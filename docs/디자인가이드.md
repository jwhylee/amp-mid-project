# 디자인 가이드 — MuBase v2

> 기획 5단계 "화면 기획"(발표자료 부록 B5-4 화면별 요소 분석표 · B5-5 상태관리 포인트)의 요약본입니다. **코드의 화면 파일 맨 위 대응표와 번호·명칭이 같아야** 합니다(UI 25점 "기획과 일치").
> 이 가이드에 없는 화면은 만들지 않습니다(감점). 화면을 바꾸면 여기 → 코드 대응표 → 원칙 카드 → 발표자료 B5-4 순서로 같이 고칩니다.
> v2가 고치는 범위: MuBase(뮤지션을 위한 AI 음악 커뮤니티 & 중고악기 장터) 안에서 방대한 정보 속에서 **내게 맞는 것을 찾고(AI 대화형 조건 검색)** · **판단하도록 돕는 것(AI 조언 · AI 상태 체크 · 시세 · 후기)**. 알림 정확도 자체는 강조점이 아니다. 커뮤니티 전체 정체성은 그대로입니다.

## 1. 화면 목록과 흐름

| 화면 | 이름(비즈니스 명칭) | 파일 | 들어오는 방식 | GET |
|---|---|---|---|---|
| A | 통합 홈 | `lib/screens/a_list_screen.dart` | 첫 화면 | `/posts?board=` · `/notices` |
| B | 게시글 상세 | `lib/screens/b_detail_screen.dart` | 쌓기(push) — A의 게시글 카드 또는 C의 추천 결과를 누름 | `/conditionChecks?postId=` · `/priceInfo?postId=` · `/usageReviews?postId=` |
| C | AI 검색 확인 시트 | `lib/screens/c_result_sheet.dart` | 덮기(modal) — A의 AI 조건 입력창에서 보내기 | `/aiResponses?id=` (미리 정한 응답) |

```
A 통합 홈 ──덮기(BottomSheet)──▶ C AI 검색 확인 시트 ──쌓기(push)──▶ B 게시글 상세 [옆으로(tab): 글 내용 | 시세 | 사양 | 사용 후기]
A 통합 홈 ──쌓기(push)──────────────────────────────────────────▶ B 게시글 상세
```

- 전환 3방식: **쌓기**(push/pop) · **옆으로**(TabBar) · **덮기**(showModalBottomSheet / showDialog).
- 목표까지 3단계: 말하기(A-2) → 조건 확인 · AI 조언(C-2 · C-4) → 상세에서 판단(B-4 · B-6). 현행은 조건을 키워드 한 줄로만 말하고, 고르는 판단은 혼자 · 시세 · 후기는 앱 밖.
- 적응형: A는 창 너비 **600dp 이상**이면 게시글 카드를 격자(GridView 2열, 900dp 이상 3열), 미만이면 목록(ListView) — `LayoutBuilder`. C 시트와 B 본문은 넓은 화면에서 최대 너비 720dp로 가운데 정렬.
- AI는 **미리 쓴 가짜 응답**입니다. 어떤 문장을 넣어도 정해 둔 응답(`/aiResponses?id=1`)을 보여 줍니다. 예시 조건 칩 2번은 결과 없음 응답(`id=2`)으로 빈 상태를 보여 줍니다. 문장 해석·추천 계산은 하지 않습니다(감점 항목).

### 1-1. 문제를 두 층으로 본다 (발표자료 06 · B5-3과 같은 말)

근본 원인: **게시글 분류(기초 설계)가 부족하고, 화면(UI)은 그 분류로 찾기 · 판단을 돕지 않는다.** — 초보일수록 막막하다(#7)

| 층 | 문제 | v2에서 |
|---|---|---|
| UI | 조건은 키워드 한 줄로만 · 결과가 왜 왔는지 안 보임 · 고를 때 도와주는 정보 없음(#7) · 공지 7줄 · iOS 뒤로가기 없음 | A-2 · C-2 · C-3 · C-4 · C-5 · B-3 · B-6 · A-5 · B-1 |
| 기초 설계 | 게시글 분류에 브랜드 · 모델이 없음(캡처 B) · 알림이 분류 대신 글자 포함으로 매칭(추정) | **데이터 구조만 제안**: `posts`에 `brand` · `model` 필드, 검색과 알림이 같은 `conditions` 구조(`type`: category · brand · price · region · exclude)를 쓴다 — `mock_server/db.json` |
| 범위 밖 | 실제 매칭 · 추천 알고리즘, 앱 안정성(유형 ③) | 구현하면 감점 → v3 |

## 4. 디자인 가이드 글 (위에서 정의한 명칭을 그대로 쓴다)

### AI 조건 입력창 (A-2)
- **목적**: 키워드 한 줄 대신, 원하는 조건을 문장으로 받는다.
- **내용**: 통합 홈 첫 줄에 가장 크게. 힌트 "예: 60만 원 이하 펜더 일렉, 앰프는 빼고". 보내면 AI 검색 확인 시트가 열린다.
- **의도**: P06 기억보다 재인 — 키워드를 정확히 기억해야 하던 문제(#5)와 엉뚱한 알림(#1 #2)의 출발점을 바꾼다.

### 예시 조건 칩 (A-3)
- **목적**: 처음 쓰는 사람도 첫 문장을 바로 시작하게 한다.
- **내용**: 입력창 아래 3개. ① "60만 원 이하 펜더 일렉, 앰프 빼고" ② "강남 주말 드럼 합주실 1만 원 이하"(빈 결과 응답 id=2) ③ "베이스 레슨 초보". 누르면 입력창이 채워진다.
- **의도**: P06 — 처음이라 어렵다(#7)는 사람에게 문장 모양을 보여 준다.

### 게시판 탭 (A-4)
- **목적**: 장터만이 아니라 합주실 · 레슨 · 구인 · 공연까지 한곳에서 오간다.
- **내용**: 장터 · 합주실 · 레슨 · 구인 · 공연 순서의 탭. 탭마다 같은 게시글 카드 목록.
- **의도**: P02 — 현행의 잘된 점(뮤지션 활동 단위 게시판, #15 #16 #17)을 지킨다.

### 공지 접기 줄 (A-5)
- **목적**: 첫 화면에서 게시글이 바로 보이게 한다.
- **내용**: 공지를 1줄로 접어 두고, 누르면 펼친다.
- **의도**: P08 — 공지 7줄이 첫 화면을 덮던 현행 문제(캡처 D)를 고친다.

### 게시글 카드 목록 (A-6)
- **목적**: 목록에서 바로 고를 수 있게 판단 정보만 보인다.
- **내용**: 제목 → 가격(굵게) → 카테고리 · 지역 칩. 넓은 화면에서는 2–3열 격자.
- **의도**: P08 — 게시글이 이미 가진 구조(카테고리 · 가격 · 지역, 캡처 B · C)를 그대로 보여 준다.

### 목록 상태 안내 (A-7) · AI 응답 상태 안내 (C-6)
- **목적**: 기다리는 중, 실패, 결과 없음을 구분해 다음 행동을 알려 준다.
- **내용**: 로딩 표시 → 오류 문장 + "다시 시도" → 빈 상태 안내. C-6의 결과 없음에는 "조건을 하나 빼 보세요".
- **의도**: P09 — 흰 화면에서 할 수 있는 게 없던 경험(#12) 대신 복구 방법을 준다.

### AI가 알아들은 조건 (C-2)
- **목적**: AI가 이해한 조건을 결과보다 먼저 확인하게 한다.
- **내용**: 내가 말한 문장을 조건 단위로 풀어 보여 준다. 예) "60만 원 이하 펜더 일렉, 앰프 빼고" → [일렉기타] [펜더] [60만 원 이하] [서울] [앰프 빼기 X]. 순서는 카테고리 → 브랜드 → 가격 → 지역 → 빼는 단어(빨간 테두리). 틀린 조건은 X로 뺀다(화면 표시만 바뀐다).
- **의도**: P05 오류 예방 — 펜더 → 앰프·베이스(#1), "esp" → "lespaul"(#2) 같은 오해를 결과를 보기 전에 고친다.

### 빼는 단어 추가 (C-3)
- **목적**: 빼고 싶은 단어를 직접 더한다.
- **내용**: 조건 줄 끝 "+ 빼는 단어" → 단어 입력 창(showDialog). 확인하면 [○○ 빼기] 조건이 하나 생긴다. 저장하지 않는다.
- **의도**: P05 — 리뷰 #2의 "제외 단어 설정" 요청에 그대로 답한다.

### AI 조언 (C-4)
- **목적**: 처음 사는 사람도 예산 · 용도에 맞춰 무엇을 고르면 좋을지 판단하게 돕는다(컨설팅).
- **내용**: AI가 알아들은 조건 바로 아래 카드. 2–3문장, 핵심만 굵게. 예) "예산 60만 원이면 **1번 매물(58만 원)이 시세 평균보다 2만 원 싸요.** 2번은 4만 원 초과지만 상태가 좋아요." "더 보기"로 펼친다. 문장은 db.json `aiResponses.advice`에 미리 써 둔 것이고 앱에서 계산하지 않는다.
- **의도**: P10 도움말 — "처음이라 어렵고 망설여져요"(#7). 저니 1단계(필요한 것 정하기)의 AI 활용 기회.

### 추천 결과 목록 (C-5)
- **목적**: 조건에 맞는 글을 게시판 구분 없이 보여 주고, 왜 맞는지 함께 말한다.
- **내용**: 게시판 라벨 → 제목 → 가격 → 맞는 이유 줄("일렉기타 · 58만 원 · 앰프 제외"). 장터 매물과 합주실 글을 섞어서. 누르면 게시글 상세로.
- **의도**: P06 · P01 — 결과가 왜 나왔는지 보이게 해 엉뚱한 결과를 바로 알아본다.

### 다시 찾기 · 알림 받기 (C-7)
- **목적**: 조건을 고친 뒤 처음부터 다시 말하지 않고 다시 요청하고, 같은 조건을 알림에도 쓸 수 있게 한다.
- **내용**: 시트 맨 아래 한 줄. "다시 찾기"(FilledButton)는 같은 임의 응답을 다시 GET한다(로딩 상태가 보인다). "이 조건으로 알림"(OutlinedButton)은 SnackBar만 띄우고 실제 등록은 없다.
- **의도**: P03 사용자 통제 · P04 일관성(검색과 알림이 같은 조건 구조). 알림은 보조 기능이고 강조점이 아니다.

### 뒤로가기 바 (B-1)
- **목적**: 어느 기기에서든 이전 화면으로 바로 돌아간다.
- **내용**: AppBar 왼쪽 위 BackButton. C에서 왔으면 시트로, A에서 왔으면 홈으로 돌아간다.
- **의도**: P03 — iOS 뒤로가기 없음(#8), 뒤로가기만 한참(#9).

### 내 조건과 맞는 이유 (B-3)
- **목적**: 상세에서도 추천 이유를 다시 본다.
- **내용**: C-5의 맞는 이유를 Chip으로. A에서 바로 들어오면 보이지 않는다.
- **의도**: P01.

### 판단 정보 탭 (B-4) · 시세 범위 막대 (B-5)
- **목적**: 사기 전에 필요한 상태 · 시세 · 사양 · 후기를 앱 밖으로 나가지 않고 본다.
- **내용**: 글 내용 · AI 상태 체크 · 시세 · 사양 · 후기 탭(장터 글만). 시세는 최저 · 평균 · 최고 막대 위에 이 매물 위치. 후기는 별점 → 한 줄 후기 목록. 값은 미리 정한 데이터이고 앱에서 계산하지 않는다.
- **의도**: P07 — 현행의 잘된 점(앱 하나로 해결, #16)을 판단 단계까지 넓힌다.

### AI 상태 체크 (B-6)
- **목적**: 사진만 보고 혼자 상태를 짐작하지 않게, 확인할 곳을 짚어 준다.
- **내용**: 매물 사진 위에 번호 ①②③, 아래 목록에 "① 바디 스크래치 — 보통 · ② 프렛 마모 — 좋음 · ③ 잭 소켓 — 확인 필요". 결과는 db.json `conditionChecks`에 미리 써 둔 것이고 실제 이미지 분석은 하지 않는다(감점 항목).
- **의도**: P01 상태의 가시성 — 초보의 망설임(#7), 저니 5단계(비교 · 판단하고 연락)의 AI 활용 기회.

### 판매자 연락 버튼 (B-7)
- **목적**: 연락 단계까지 흐름을 보여 준다.
- **내용**: 화면 아래 고정 버튼 → 확인 창(showDialog) "판매자에게 연락할까요? (데모: 실제 연락은 되지 않습니다)" · 취소 / 확인 → SnackBar.
- **의도**: P03 — 잘못 눌러도 취소할 수 있다. 실제 연락·채팅은 구현하지 않는다.

## 5. 상태관리 포인트 (표시만 — 구현하지 않는다)

코드에서는 `// STATE: <데이터> → <보여질 위젯>` 주석으로만 남깁니다. 모아 보기: `grep -rn "STATE:" lib`

| # | 바뀌는 데이터 | 어디서 바뀌나 | 보이는 곳(화면 · 요소 번호) | 코드 주석 위치 |
|---|---|---|---|---|
| S1 | 입력 문장 | A-2 타이핑 · A-3 예시 칩 누름 | A-2 → 시트의 C-1 | `a_list_screen.dart` |
| S2 | 선택된 게시판 | A-4 탭 누름 | A-4 · A-6 (GET /posts?board=) | `a_list_screen.dart` |
| S3 | 서버 응답 상태(로딩 · 오류 · 데이터) | 화면 열림 · 다시 시도 · C-7 다시 찾기 | A-7 · C-6 | `a_list_screen.dart` · `c_result_sheet.dart` |
| S4 | AI가 알아들은 조건 목록 | C-2 X로 빼기 · C-3 빼는 단어 추가 | C-2 | `c_result_sheet.dart` |
| S5 | AI 조언 펼침 / 접힘 | C-4 "더 보기" 누름 | C-4 | `c_result_sheet.dart` |
| S6 | 선택된 판단 정보 탭 (AI 상태 체크 포함) | B-4 탭 누름 · 옆으로 밀기 | B-4 · B-6 | `b_detail_screen.dart` |

화면 안 표시는 `setState`로만 바꿉니다. Provider · Riverpod · Bloc 등 상태관리 구현과 영구 저장은 하지 않습니다(안내문 4장 감점).
